# Playground / Blog 文章维护规范

## 入口与修改位置

- 文章由仓库根目录 `build_blog.py` 中的 `render_blog()` 生成；运行 `python3 build.py` 构建全站。不要只编辑生成后的 `blog/index.html` 或 `blog/astradraw/index.html`，否则下次构建会覆盖。
- 当前真实文章内容保存在 `blog/posts.json`，文章结构在 `build_blog.py`。新增文章应扩展生成入口与真实文章数据，沿用同一页头、文章模板与页脚；不要复制一套孤立页面。
- 学术主页入口名为 Playground，现有 Blog URL `/blog/` 保持兼容。未获新的明确要求时，不调整学术主页其他区块、头像、页面顺序或旧站内容。
- 现有样式分工：`blog.css` 基础布局，`article-components.css` 阅读组件，`interactions.css/js` 通用微交互，`reading.js` 目录与人物，`icons.css/js` 图标，`navigation.css/js` 导航，`footer.css` 页脚与云层，`panel-motion.css/js` 彩虹面板装饰，`link-motion.css/js` 关闭按钮和链接箭头，`reactions.css/js` 爱心互动。在负责对应行为的文件里修改，避免新增冲突的重复规则。

## 内容原则

- 所有项目、链接、经历、图表、日期与结论必须有用户提供的内容或真实可查的项目材料支持。当前 AstraDraw 的文字、配图与可编辑 PPT 均有真实仓库来源，保留引用和目标链接。
- 不为填满版面编造文章、发布日期、阅读量、评论、研究效果、个人经历、点赞或订阅服务。RSS 可以使用真实 feed；没有实际邮件服务时不放邮件订阅表单。
- 文章正文使用明确具体的表达；项目说明避免空泛口号。中英内容使用现有 `tr()` / `data-en` / `data-zh` 机制，切换语言不应破坏内嵌链接或 SVG。
- 现有收录约定是仅主页可索引；Blog 页面保留 `noindex, follow`，不要把文章加入当前只含主页的 sitemap，除非用户明确改变约定。

## 排版与组件

- 以 Josh Comeau 参考站的阅读节奏和交互结构为依据，使用本站真实内容与自己的身份元素。保留已有来源说明。参考审计在工作区 `output/josh-reference/` 下：`DEEP-INTERACTION-AUDIT.md`、`CLOUD-SOURCE-MANIFEST.json`、`FOOTER-NAV-IMPLEMENTATION.md`。
- 使用已经取得许可并随站点保存的字体。不把免费 Regular 宣称为 Medium；不要因浏览器能下载就加入未获许可的付费字体文件。
- 正文为 18px / 27px；段落下距 1.25em。桌面正文宽约 686px，右侧目录 250px，间隔约 100px。手机正文仍保持可读字号，左右 16px 空间。
- H2 采用已有颜色和层级，段前 48px、段后 32px。为每节提供稳定、唯一、有语义的 id；目录必须对应真实标题。
- 保留标题左侧 SVG 锚点、桌面浮动目录、顶部阅读导航。锚点点击应避开固定页头，键盘焦点清楚。不要把标题锚点替换成常驻普通 `#` 字符。
- 提示框使用 `.article-note`：只承载真正的补充说明，正文 16px / 24px，标题 18px / 27px。沿用浅色/暗色适配、弯曲边角、桌面 info 标记、手机边缘展开。不能仅为了装饰每一节都加提示框。
- 普通操作示例使用左对齐正文 `.instruction-example`，不要排成大引号、居中斜体的装饰性引文。真正的引用才考虑 `<blockquote>`；先核对参考站同类内容的实际使用场景，不因源码里存在某个组件就机械套用。不要伪造他人引语或作者署名。
- 图注只保留图片说明，不附加“打开 PPT”等行动入口；相关文件和项目链接放在文末。
- 图片使用 `<figure class="article-figure">`、真实图片和 `<figcaption>`。提供内容正确的 alt、真实宽高、清晰来源或原图链接。正文图不应被 hover 调暗，不擅自改动研究图内容。
- 文章不添加标题前返回链接、手机折叠目录、文末项目卡片或额外返回工具行。真实资源链接放在普通正文中，之后直接接最后更新日期与访问量。
- 更新时间来自文章数据中的真实编辑日期；访问次数仅接受服务端有效结果，不编造历史量。数码计数器点击只切换灯光，不增加访问次数。
- 手机 H1 保持 36px、H2 保持 32px/48px；目录在宽度不超过 1064px 时隐藏。
- 代码块、标签页、折叠区、表格、交互演示仅在正文确有需要时新增；不要为当前短文塞入空组件。新增时同时实现键盘操作、展开状态、焦点、移动端布局和减少动画，不只画外观。

## 交互一致性

- 首次进入时页头工具按已有延迟逐项出现；图标使用自身短暂弹性反馈，不能用统一持续 hover 位移替换。
- Read more 的主箭头和后续箭头是分开的交互；声音有独立开启开关、静音与存储约定，离开时及时停止。不要给所有链接添加通用提示音。
- 全站浅色/暗色与语言选择必须连续保留。人物使用已有独立光照层和表情层，不用统一 brightness 滤镜替代，也不改学术主页真人照片。
- 彩虹设置只影响当前浏览器；面板装饰不能拦截指针或键盘。减少动画时关闭装饰动画，并清理重复计时器。
- 云层是大幅 SVG 居中裁切，不是把整条路径压缩到视口宽。调整云层时沿用 `CLOUD-SOURCE-MANIFEST.json` 的各页面尺寸、裁切与断点，核对人物与云峰的相对位置。
- 顶部分类菜单只在点击或键盘操作时展开，不使用悬停自动打开；栏目切换沿用共享浮层的尺寸与位置过渡。
- 文章爱心从 0 开始，最多 16 次，只记录当前浏览器的真实点击，并明确标注；不把本机计数包装成全站总数。
- 不出现无功能的按钮或跳转目的不明的导航。Playground 顶部菜单保留站内浏览意图；学术主页作为明确命名的独立链接。

## 交付检查

- 构建并检查修改没有意外改变学术主页、旧站或已有路由。
- 对实际受影响的文章组件检查桌面和手机、浅色和暗色、中英文；确认没有水平滚动、文字溢出、配图变形或链接失效。
- 有交互变更时检查键盘、焦点返回、减少动画和重复开关；根据实际修改选择测试，不为单纯可逆文案改动编写重复实现的测试。
- 只有经过实际浏览或测试才能声称行为已验证；不要把静态截图检查说成音效、所有交互或完整视觉一致性的证明。
